# Step 7: UI 폴리싱 & E2E 테스트

## 목표
대시보드의 시각적 품질을 최종 점검하고, 전체 흐름(백엔드→프론트엔드)을 검증한다.

## 작업

### 1. 시각 품질 점검
- [ ] 다크모드 배경/카드 색상이 UI_GUIDE와 일치하는지
- [ ] 상승/하락 색상이 올바르게 적용되는지 (오렌지/블루)
- [ ] 카테고리 뱃지 6개가 각각 다른 색상인지
- [ ] 폰트(Inter)가 로딩되는지
- [ ] 숫자에 `tabular-nums`가 적용되는지
- [ ] 금지된 AI 슬롭 패턴이 사용되지 않았는지 (blur, glow, gradient orb 등)

### 2. 애니메이션 점검
- [ ] 카드 로딩: fade-in (0.3s)
- [ ] 리스트 아이템: slide-up (0.3s)
- [ ] 유가 숫자 변경: transition (0.2s)
- [ ] 불필요한 장식적 애니메이션이 없는지

### 3. 프론트엔드 빌드 테스트
```bash
cd frontend && npm run build
cd frontend && npm run lint
```

### 4. 전체 흐름 수동 테스트
1. 백엔드 시작: `cd backend && uvicorn app.main:app --reload --port 8000`
2. 프론트엔드 시작: `cd frontend && npm run dev`
3. 대시보드 접속 (`http://localhost:5173`)
4. 확인 항목:
   - 유가 차트가 데이터를 표시하는지
   - 뉴스 기사가 표시되는지
   - AI 브리핑이 로딩되는지
   - 요인 게이지가 표시되는지
   - 차트↔뉴스 인터랙션이 동작하는지

### 5. 에러 상태 처리 확인
- 백엔드 미실행 시: 프론트엔드에 에러 메시지가 표시되는지
- API 키 누락 시: 안내 메시지가 표시되는지
- 데이터 없음 시: 빈 상태(Empty state)가 표시되는지

## AC (Acceptance Criteria)
1. UI_GUIDE.md의 모든 디자인 규칙이 준수된다
2. AI 슬롭 안티패턴이 사용되지 않았다
3. `npm run build`가 에러 없이 완료된다
4. `npm run lint`가 에러 없이 완료된다
5. 프론트엔드→백엔드 전체 흐름이 동작한다
6. 에러 상태가 적절하게 처리된다
